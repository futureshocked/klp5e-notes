Project (Warm-up): 4×8×8 LED Matrix Array

In the capstone project for volume 2, which you will work on in the next chapter, you will need to author custom parts. But before doing that, in this warm-up project you will do something almost as valuable. You will work at scale by using KiCad’s features that allow you to duplicate a portion of a board with just a few clicks. The board of this project includes four 8-by-8 LED matrices sitting side by side under the control of a microcontroller. The main objective of this project is to draw one section well and then reuse that work instead of hand-placing the components for the other three sections. Four matrices give you 256 individually addressable LEDs in a display band 80 mm wide and 20 mm tall, which is enough to scroll a message, draw a bar graph, or count something down in characters large enough to read across a room.

There are two things to notice in the sketch. The first is that the drawing is essentially one cell repeated four times. The cell contains a matrix display, a display driver placed on the back of the board, a current-setting resistor and a pair of decoupling capacitors. There is nothing different between the cell copies except the reference designators. The second is scale. The board is roughly 100 mm by 50 mm, but the exact dimensions are something we’ll determine in the layout editor. However, the 80 mm display band inside it comes from the four 20 mm matrices placed edge to edge. That is the only fixed dimension on the sketch.

I built the first version of this board in the fourth edition of KiCad Like a Pro as a clock. This new modernised edition keeps the display, the two buttons and the power switch. I have also added a USB-C power receptacle (because it’s 2026), a P-channel MOSFET load switch so that the slide switch no longer has to carry the display current, and a new simplified board shape to make it easier to place the board in a project box. My inspiration for designing this gadget was the classic Pomodoro timer1. For such a gadget, keeping time is not needed, and that is why I did not include a real time clock. I just need to be able to choose a timer preset, like a 10- or 15-minute session, and start/stop/reset the clock. This board counts down a work interval in the Pomodoro style, which the two buttons choose and start. Counting down a known number of minutes needs no absolute time reference, so nothing on the board has to know what day it is.

What you are building is that LED matrix cell, four times over, driven from the Arduino Nano across three wires (Figure 7.2). You can consider this as a base project rather than a finished product. If you want time and date keeping capability, the neatest route is not to add an RTC chip but to swap the Arduino Nano for one of the WiFi-capable modules in the same footprint, and let it fetch the time from the network. The schematic barely changes, and you get many more capabilities in return, because a board on the network can also be controlled remotely. That opens up capabilities such as scrolling live notifications, a status board for something you run at home, and a countdown someone else can start from a phone.

Let’s start by reviewing the main learning objectives of this project, and then go and build it.

What This Project Teaches You

I put this project before the capstone to help you become fluent with the machinery of a large schematic. The capstone, in the next chapter, builds on top of that fluency. These are the five new skills you’ll practice:

  1. Design blocks. You will capture one working cell once and stamp it out three more times, instead of drawing the same circuit four times. This is the main new skill of the chapter. You will meet it again in Chapter 9, where the four-motor extension uses the same feature on a bigger board.
  2. Working at scale. The finished sheet carries several times the parts of anything you built in Volume 1, and many times the wires and nets. Those boards had only a few components each. Habits that work on a handful of parts, such as checking each connection by eye, eventually stop working as the size of the board grows.
  3. Net classes that stand out. Chapter 3 set up the electrical half of a net class, the track widths and clearances. In this project, you fill in the graphic columns as well, so that the power rails stand out on the editor by using a distinct colour and weight. You will use net classes again in Chapter 8, for the motor nets (a motor draws its current continuously, while a multiplexed display draws it in short, hard bursts).
  4. Net class assignment patterns matching multiple nets. Chapter 3 taught you the pattern syntax on a board where a pattern matched a few nets. On this board, one pattern matches over thirty nets.
  5. Reading violations, not counting them. A violation that describes something you have not done yet is information rather than an error. You will learn how to use the information provided by the ERC or the DRC to improve your design, or to tell KiCad what is good or bad via the use of custom rules.

In this project, you will not author a symbol or a footprint from scratch. One part on this board, the LED matrix itself, is not in KiCad’s standard library, and I supply it ready-made in the book’s project library for you to import.

The Board We’re Building

As I mentioned earlier, the array is built from a single repeating unit I will call a ‘cell’. Each cell contains an 8-by-8 LED matrix, a driver chip that turns simple serial data into sixty-four individually controlled LEDs, and the local decoupling capacitors that driver needs. Four cells sit side by side and chain their data lines, so the microcontroller talks to the first cell and the rest follow. Add a microcontroller, a power input and a little supporting circuitry, and that is the board.

Here is everything on it:

The whole array runs on three signals from the Arduino Nano. Signals CLK on D13 and LOAD on D10 go to all four drivers at once, and DIN on D11 goes only to the first one. Each driver passes what it does not need out of its DOUT pin and into the next driver’s DIN, so the four chips form a chain that the Nano addresses as one long shift register. The two buttons are connected to D2 and D3, each held high by a 10 kΩ pull-up and pulled low when pressed.

Everything except the matrix comes from KiCad’s standard libraries, so that you can spend all of your attention on the structure of the schematic rather than on looking for parts.

Sourcing the Parts

One of the parts in this project is not available in the standard library, so I have sourced it externally. I am also going to highlight a couple of potential traps worth knowing about before you order any of the parts, if you want to assemble this board.

The matrix comes from the book’s project library. The symbol LED_Matrix_TA08-81GWA and the footprint LED_Matrix_TA08-81_20mm_8x8 are both available in klp5e-ch07.kicad_sym and klp5e-ch07.pretty, which ship with the project files in the book’s GitHub repository. Add them to this project’s library tables the way Volume 1’s Chapter 6 showed you, and the part is waiting in the chooser when you reach for it. If you prefer, you can download a TA08 part from a parts service like Snapeda. I did compare the one I created and share with you in the project library against one I found online while building this board. The two agree on every pin and every dimension. I decided to use my own because it puts the pin rows along the top and bottom edges rather than the left and right, which leaves the seam between neighbouring cells free for wiring. Also, mine insets the courtyard slightly so that four matrices can be placed edge to edge without raising clearance violations against each other. Figure 7.3 shows the footprint open in the Footprint Editor, which is where you can confirm it is properly installed after you add the library.

Figure 7.3: The project’s LED_Matrix_TA08-81_20mm_8x8 footprint, open in the Footprint Editor after the klp5e-ch07 library has been added. The library tree on the left shows the two parts the library ships, and the properties panel confirms where the footprint is coming from. On the canvas, the sixteen pads run in two rows of eight along the top and bottom edges, with pad 1 square and marked by the silkscreen dot at the bottom left. That arrangement is the reason for choosing this part over a catalogue one: it leaves the left and right edges clear, so that four of these can butt against each other and still have somewhere for the wiring to go.

The TA08 is column anode, and the TC08 is column cathode. These symbols are the same physical package with the internal diode array reversed, they sit next to each other in most catalogues, and the part numbers differ by one letter. If you substitute one for the other without re-mapping which driver output goes to which matrix pin, you will build a display that lights nothing at all and shows no sign of why. Be careful to order the TA08.

The matrix has a 2.5 mm pin pitch, not 2.54 mm. It is metric, and it is the most important dimension number on this board. You can measure it for yourself on the footprint with the PCB Editor’s measurement tool, which is worth doing once so you can confirm it really is 2.5 mm (Figure 7.4). In the schematic this number doesn’t matter, because the symbol’s pins sit on KiCad’s standard 1.27 mm grid just like the pins of every other symbol. But in the PCB Editor it is very important. The Arduino Nano is imperial, on a 2.54 mm header pitch with its two rows 15.24 mm apart. Its neighbours are metric: the slide switch shares the matrix’s 2.5 mm pitch, and the two push buttons sit on a spacing of their own, 6.5 mm one way and 4.5 mm the other. No single grid lands on all of that. The problem appears first in placement, when the cells have to sit at exactly 20.0 mm, which is 8 × 2.5 mm, and 20.0 mm is not a whole number of 2.54 mm steps. All this means that if you stay on the 100 mil grid you used for the Nano then the nearest you can reach is 20.32 mm, a 0.32 mm seam between neighbouring panels that grows to almost a millimetre across the four. So, you should match the grid to the job, as you did in Chapter 2, and lay this board out in millimetres.

Figure 7.4: The measurement tool laid across pads 1 and 2 of the matrix footprint, reading x: 2.500 mm. Not 2.540 mm. The forty thousandths of a millimetre missing from each step are what the placement section later has to work around, because eight of them add up to 0.32 mm across a single panel.

One more thing worth knowing before you draw is that the MAX7219 stock symbol arrives with no footprint assigned, so when you get to the footprint step you will have to choose its package yourself. It does carry footprint filters, SOIC*7.5x15.4mm*P1.27mm* and DIP*7.62mm*, which narrow the list to the wide-body SOIC this board uses and the through-hole alternative. Whether you see that short list or the whole library depends on the filter buttons in the Footprint Assignment tool’s toolbar, and I will come back to them at the footprint step. Either way, an unassigned footprint is normal for this part, not a sign that anything is wrong.

Planning the Power Before You Draw

The display on this board draws significant current, especially when most or all of its LEDs are on. Therefore, we will need to carefully estimate the maximum current draw to expect.

Each MAX7219 sets its LED current ceiling with a single resistor, RSET. At the 10 kΩ this board uses, each segment output can source about 40 mA. The datasheet characterises the part at 9.53 kΩ for exactly 40 mA, and 10 kΩ lands a little under that, which is the direction to err in.

The word ‘Segment’ in that sentence is borrowed, and so is ‘digit’. Both come from alphanumeric and numerical displays. The MAX7219 was primarily designed to drive seven-segment numerals. For that reason it has eight digit outputs, DIG0 to DIG7, one for each numeral position, and eight segment outputs, SEG A to SEG G plus SEG DP, one for each bar of the figure plus the decimal point. Eight digits of eight segments each come to 64 LEDs.

An 8-by-8 matrix is also 64 LEDs, and that is why we can use the MAX7219 to drive it. The pin names stayed, but the geometry changed. On this board the eight SEG outputs source current into the matrix’s eight columns, which are its anodes, and the eight DIG outputs sink that current out of its eight rows, which are its cathodes. A digit is therefore one row of the matrix, and a segment is one column of it (Figure 7.5).

Figure 7.5: The same sixteen outputs, seen twice. On the left is the arrangement the names were invented for: eight segments make one numeral, and eight numeral positions sit side by side. On the right is what those outputs drive here. The eight SEG outputs feed the columns and source current into them, the eight DIG outputs take it back out of the rows, and DIG2 is drawn as the row the driver has switched on. Every LED along that row can be lit at once, which is where the 320 mA comes from, while any one column carries only its own 40 mA. Below, the driver works through the eight rows in turn, each one lit an eighth of the time.

The multiplexing is the next part of this arrangement to understand. The driver turns on one digit at a time, meaning one row at a time, and cycles through all eight fast enough that your eye sees a steady picture rather than a flicker. Each LED is lit one-eighth of the time, and so it is tempting to divide by eight and budget for the average. But the tracks do not carry the average current. At any instant exactly one row is active and all eight LEDs along it can be on, which puts 8 × 40 mA, about 320 mA, through that one driver. This current is drawn in hard bursts rather than smoothly. The four drivers plus the Arduino Nano (at roughly 20 mA) come to about 1.3 A at worst case. That is the number the power supply and the tracks have to be sized for.

The LEDs themselves are comfortable at that ceiling. At one-eighth duty, 40 mA averages 5 mA per LED, against the TA08’s 25 mA continuous rating, and the 40 mA peak sits well inside its 140 mA pulsed rating. The datasheet quotes 140 mA at one-tenth duty, and this board runs one-eighth duty, which means that the LEDs have to work slightly harder. The gap between 40 mA and 140 mA is wide enough to absorb the difference. Remember also that the MAX7219 carries an intensity register, so software dims the display below whatever RSET allows. RSET sets a ceiling rather than a working value, and copper sized for the ceiling will not be the cause of a fault.

That number drives three of this board’s design decisions.

The supply. 1.3 A will not come through the Nano’s onboard regulator, or the Nano’s own USB lead. This board brings its power in over a USB-C receptacle, J1, and the Nano’s socket is used as a programming lead only. Both cables can be plugged in at the same time.

Component J1 is the same GCT power-only receptacle you met in Volume 1’s breadboard supply. It has two VBUS contacts, two GND contacts, CC1 and CC2, and no data pins at all. Remember that a USB-C source waits to be asked before it switches its 5 volts on, and that is done by tying each CC pin to ground through a 5.1 kΩ resistor. Those are R7 and R8 here.

What is new on this board is how much it then draws. Those two resistors claim default USB power, which is 500 mA, and this board draws 1.3 A. That works in practice, because a Type-C source, such as a laptop port or a USB-C power supply, enforces its own limit, and a supply advertising 1.5 A or 3 A will deliver what is drawn from it. However, the board is not measuring the voltage on CC and cannot tell you what it is plugged into. Checking the supply is therefore your responsibility, not something the circuit does for you.

Feed J1 from a regulated 5 V supply rated at 1.5 A or more. Nothing downstream will regulate or filter what you plug in, because VBUS becomes the board’s +5V rail and +5V goes straight to the Nano’s 5V pin, bypassing the onboard regulator entirely. The alternative is to feed the Nano’s VIN pin instead and let the onboard regulator do the work. The problem with this is that the regulator will not survive 1.3 A, so don’t do it!

The switch. 1.3 A is also far more current than a slide switch of this size is built to carry. The C&K JS202011AQN is rated for 0.3 A at 6 V, so this board asks more than four times what its contacts are specified for. On this board the switch does not carry it. For this, we use Q1, an AO3401A P-channel MOSFET rated 4 A, that sits between VBUS and +5V as a ‘high-side load switch’. Because of Q1, SW1 does nothing but drive its gate. There is also R9, at 100 kΩ, which ties that gate to VBUS. In the off position the switch leaves the gate on an unconnected pin, so R9 holds it at VBUS, there is no voltage between gate and source, the MOSFET is off, and the rail is dead. When you slide it to the ON position, the gate reaches ground through R10, 10 kΩ, so the two resistors divide VBUS between them, which puts the gate about 4.5 V below the source and turns the MOSFET hard on. SW1 carries the 45 µA that flows through the divider, and the copper carries the 1.3 A. That is three extra parts, and in exchange the slide switch never carries the load current.

The copper. +5V and GND get a Power net class of their own, just as the motor driver’s supply did in Chapter 3. We’ll set this net class up in Schematic Setup now. Work the width out yourself in the Track Width tab of the Calculator Tools application, the way Chapter 3 showed you, rather than taking my word for it. Enter 1.3 A, a 10 °C temperature rise and 1 oz copper, and read the external-layer answer (Figure 7.6). It comes out at about 0.44 mm. The class specifies 1.00 mm, which carries about 2.39 A, because there is no reason to route a power rail at the minimum the arithmetic allows when the board has room for better.

Figure 7.6: The Calculator Tools application on its “Track Width” page, worked for this board’s power rail. The two numbers you supply are the current and the temperature rise you will tolerate (❶), the copper weight goes in as a track thickness of 1 oz/ft² (❷), and the answer to read is the one under “External Layer Tracks” (❸), because both power rails on this board are routed on the outside. It comes back with 0.438888 mm, and the resistance, voltage drop and power loss below it are worked for the 20 mm conductor length in the parameters panel. The internal-layer figure beside it, 1.12 mm, is what the same current would need buried between layers, where the copper has nowhere to shed its heat.

There is a third class this board could reasonably have. I will explain it, and leave it up to you if you want to introduce it. Each driver connects to its matrix through sixteen nets. Of those nets, eight carry columns and eight carry rows. They look like logic, but one group of them is not. A column net carries a single LED’s 40 mA, but a row net carries the entire active digit, which can draw the full 320 mA. A designer who gave those thirty-two row nets a class of their own would be well justified in doing so. I decided to keep them on Default at 0.25 mm because at 1 oz copper 0.25 mm carries about 0.87 A, so the 320 mA peak clears by nearly three times, and over a 20 mm run the track is about 39 mΩ, which drops around 13 mV. There is wide margin, and the drop is very small.

The Process, With One Addition

You already know the process. We will use the eight-step schematic workflow from Volume 1, which does not change because the board got bigger:

  1. Create the project and schematic. Create a home directory for the design and open the editor.
  2. Place symbols. Drop a symbol for each part in the circuit.
  3. Annotate. Give every part a unique reference designator.
  4. Set component values. Tell each part what it actually is.
  5. Wire and label. Connect the pins, and name the connections that matter.
  6. Assign footprints. Tell each symbol which physical part it will become.
  7. Electrical rules check. Ask KiCad to find your mistakes while they are still free to fix.
  8. Hand off to layout. Save, and pass the design to the PCB Editor.

The one addition sits between steps 5 and 6, which is the main focus for this chapter. Once the first cell is placed, annotated, valued and wired, you capture it as a design block, that is a named, saved copy of a working piece of circuit, stored in a library. You can then drop this design block back onto the sheet as a unit. Then you stamp it (copy it) three more times.

The stamped copies arrive with question marks where their reference designators should be, because KiCad has no way to know which U they ought to be until they are on the sheet. That means step 3 runs a second time, after the stamping.

Schematic: Setup

Step 1, create the project. Create a new project, give it a name without spaces, and open the Schematic Editor onto its blank sheet. Set the page to A3 in Page Settings and fill in the title block, because this board will not fit comfortably on A4. Add the project’s klp5e-ch07 symbol and footprint libraries to this project’s library tables while the sheet is still empty, so that the matrix is waiting in the chooser when you reach for it.

Next, set up the net classes before there is anything on the sheet to apply them to. Open Schematic Setup, go to the Net Classes page, and build two classes (Figure 7.8).

Figure 7.8: The Net Classes page with both classes defined. The upper table carries the classes themselves, and the Power row has its graphic columns filled in rather than left blank: a wire thickness of 0.254 mm, a deep violet colour swatch, and a line style set explicitly to Solid. The lower panel is where nets are attached to a class by pattern, and the panel on the right previews what the selected pattern currently matches, which here is the single net +5V.

The Power nets carry the wide copper with a 1.00 mm track width, 0.30 mm clearance, and 0.80 mm vias with 0.40 mm drills. Default keeps the 0.25 mm track width you routed logic at in Chapters 3 and 4. Assign +5V, GND and VBUS to Power using the assignment patterns *+5V, *GND and *VBUS. VBUS inherits the same copper as +5V because it is the same current: it is the length of rail between the receptacle and the load switch, upstream of everything the switch controls. All three come from power symbols, so they arrive at the matcher as plain names without a sheet path in front of them, and the leading wildcard costs nothing while making the pattern robust if you later push the circuit down into a sub-sheet.

To make the power nets easy to see in the schematic, fill in the graphic columns on the Power row as well. I made mine a deep violet at 10 mil (0.254 mm, which is what the dialogue displays), with the line style left explicitly on Solid.

If what you see on your screen disagrees with mine in the book, check Preferences → Schematic Editor → Display Options. Here you’ll find a setting called Highlight netclass colours. With it switched on, the wire keeps the theme’s ordinary green and the net class colour is drawn as a halo around it instead of replacing it. It is switched off in the figures in this chapter, which is why the wires themselves are violet. If yours come out green with a violet glow, that setting is the reason, and either behaviour is fine as long as you know which one you are looking at.

Finally, it is worth remembering that a net class track width is the width KiCad routes at by default, not a limit it enforces. Nothing stops you from putting a 0.2 mm track on the +5V net. The project closes that gap with a custom design rule, in the form the capstone uses:

(rule "Power minimum width"
    (constraint track_width (min 0.8mm) (opt 1.0mm) (max 2.0mm))
    (condition "A.hasNetclass('Power')")
)

That rule does not live in Schematic Setup with the net classes. It is typed into the board’s own Board Setup, on the “Custom Rules” page, and it will wait there until you reach the layout half of the chapter (Figure 7.9). With it in the project, a power track that is too thin will trigger a design rules violation rather than passing quietly.

Figure 7.9: The same rule entered on the “Custom Rules” page of Board Setup, under “Design Rules” in the left-hand tree. The editor checks the syntax as you type and reports “No errors found.” below the text, which is worth watching for, because a rule that will not parse is silently not applied. Note what the condition says: it selects by net class rather than by net name, so the rule keeps working when you add another power net later, as long as you assign it to Power.

Building the First Cell

Now, we will draw the first design block which makes up one cell.

Step 2, place the symbols. Five symbols make a cell: the MAX7219 driver, the LED_Matrix_TA08-81GWA from the book’s library, a resistor for RSET, and two capacitors for decoupling. Place the driver first and then the rest off it, with the matrix to its right so that the driver’s outputs face the matrix’s inputs, the resistor above and to the left, and the two capacitors to the left with room for their power symbols above and below (Figure 7.10).

Figure 7.10: The five symbols of the first cell, placed and nothing else. No wires, no values, and every designator still a question mark: U?, DS?, R? and two C?. The arrangement is doing real work even at this stage. The driver’s sixteen outputs on its right face the matrix’s sixteen inputs on its left, in the same order, which is what turns the wiring step into sixteen straight lines instead of a knot.

Step 3, annotate. Give the five parts their reference designators, either by letting auto-annotation hand them out as you place, or with the Annotate Schematic tool afterwards (Figure 7.11). You should end up with U1, DS1, R1, C1 and C2, and no question marks left anywhere.

Figure 7.11: The same five symbols after annotation. U? has become U1, DS? has become DS1, and the passives are now R1, C1 and C2. Their values are still the generic R and C that the symbols shipped with, because annotating a part says which one it is, not what it is. That is the next step.

Step 4, set the values. Three values to set, and each one is a decision rather than a formality (Figure 7.12):

  • R1: 10k. This is RSET, and it is the resistor that fixes the 40 mA per-segment ceiling the whole power budget was built on. The datasheet characterises the part at 9.53 kΩ; 10 kΩ is the nearest value everyone stocks and lands a little under 40 mA, which is the safe direction to miss in.
  • C1: 100n. The small ceramic that shorts the fast switching noise to ground close to the chip. A multiplexed driver supplies 320 mA from one digit to the next several thousand times a second, so this is not an optional garnish.
  • C2: 10u. The bulk reservoir that supplies those bursts locally, so that they are not drawn down the length of the board every time a digit changes.

Figure 7.12: The cell with its three values set. R1 now reads 10k, C1 reads 100n and C2 reads 10u, in place of the generic R and C of the previous figure. Everything else on the canvas is exactly where it was.

Step 5, wire and label. The driver connects to the matrix through sixteen nets, and the choice of matrix symbol makes this step easy. The matrix symbol’s pins are ordered to match the driver’s right-hand side, so the sixteen connections are sixteen straight horizontal wires, drawn one under the next, with nothing crossing anything (Figure 7.13). If you find yourself drawing a diagonal or routing a wire around the outside of a symbol, stop and check which pin you are on, because at this point in the board a mistake is easy to fix, but if you only notice it later, the effort will be much greater.

Then, wire the power and the control lines:

  • V+ on pin 19 goes to +5V, and both ground pins, 4 and 9, go to GND. The MAX7219 has two ground pins and they are not alternatives; leaving one unconnected gives you a chip that half works in ways that are unpleasant to diagnose.
  • ISET on pin 18 goes through R1 to +5V.
  • Each capacitor sits between +5V and GND with its own pair of power symbols, right beside the driver it serves.
  • CLK and LOAD get labels of those names, because they are shared by all four drivers.
  • DIN and DOUT get no labels at all. Leave them as bare pins. This matters enormously and I will explain why in the next section, but the short version is that a label here would eventually short all four drivers together because these nets are used for the communication between the cells.

Figure 7.13: The first cell, fully wired. The sixteen driver-to-matrix connections run as sixteen straight horizontal lines with nothing crossing anything. CLK and LOAD arrive on the left as labels, because those two signals are shared. DIN and DOUT at the bottom of the driver are still bare pins, drawn with the small open circle that means nothing is attached, and that is deliberate. An important characteristic of design blocks to remember is that a design block reproduces the labels it captured. Any net label inside the block is copied verbatim into every stamped instance, which means every instance ends up on the same net. For CLK and LOAD that is what you want, because all four drivers do share those two signals, and the block having them saves you drawing them four times. For DIN and DOUT, not so. Four copies of a block containing a label called DIN gives you four drivers with their data inputs wired together, and four copies of a DOUT label ties every output to every input. The chain would collapse into a single net, all four chips would be driven in parallel, and the schematic would look correct while describing a circuit that does not work. That is why DIN and DOUT were left as bare pins in the last section, and why the links between cells get their own unique names after the stamping rather than before it.

MCU, Power, and Controls

Before making copies, finish the parts of the board that exist only once, so that you can prove one channel works before you multiply it.

Steps 2 to 4 again, for the single parts. Place and annotate the Arduino Nano, the USB-C receptacle, the AO3401A, the SPDT slide switch, the two push buttons and the six resistors that go with them, then set their values (Figure 7.17): 5.1k for R7 and R8, 100k for R9, 10k for R10, and 10k for the buttons’ pull-ups R5 and R6.

Wire the power input as described in the power section, in three steps:

  1. The receptacle. J1’s two VBUS contacts tie together and become the VBUS net. Its two GND contacts and its shield stake go to GND. CC1 and CC2 each reach GND through their own 5.1 kΩ resistor, R7 and R8.
  2. The load switch. VBUS goes to Q1’s source. Q1’s drain becomes the +5V rail that feeds everything else on the board. R9 bridges gate to source, and R10 runs from the gate to SW1’s common pin, which is pin 2 on both the symbol and the real part.
  3. The switch. One of SW1’s two throw pins, pin 1, goes to GND. The other throw, pin 3, is left unconnected, deliberately, and you will tell KiCad so with a no-connect flag at the ERC step rather than wiring it to something to keep the checker quiet. Slide the switch one way and the common meets GND, which pulls the gate down through R10 and turns the rail on. Slide it the other way and the common meets nothing, so R9 holds the gate at VBUS and the rail is off.

One thing about SW1 is worth settling now to prevent confusion later. The symbol is a three-pin SW_SPDT, but the footprint you will assign in step 6 is the six-pad SW_CK_JS202011AQN_DPDT_Angled, because the C&K part that fits this board is a two-pole switch. This board needs one pole, so the second pole’s three pads sit on the board with nothing on them. That is a deliberate choice rather than an oversight. The spare pads cost nothing, they raise no violation, and the part is the one you can actually buy. Order the DPDT part, not an SPDT one, or it will not fit the land pattern.

Each button ties its Nano pin to ground when pressed, with a 10 kΩ pull-up holding that pin high the rest of the time.

Stamping Out the Other Three

Place the MAX7219-Cell block from the Design Blocks panel three more times (Figure 7.19), arranging the four cells in a 2×2 grid with the cell you already wired in the top left. Extend the cascade. With the copies placed, link them into a chain that runs top left to top right, top right to bottom left, and bottom left to bottom right. Every hop goes from one cell’s DOUT to the next cell’s DIN, and each gets its own label, LINK1, LINK2 and LINK3 (Figure 7.20). We now have three uniquely named nets, one per gap, which make this a chain rather than a bus. Figure 7.20: The cascade, drawn as three pairs of labels rather than three long wires across the sheet. LINK1 leaves the first cell’s DOUT (❶) and arrives at the second cell’s DIN (❷). One thing not to do yet is run the ERC. Until the copies’ U?, DS?, R? and C? designators are made unique, KiCad cannot tell three components from one component mentioned three times, and it will tell you so, with a banner warning that the results are incomplete and dozens of errors reporting correctly drawn wires as not connected to anything.

One last thing before continuing with the layout is a reminder that a clean ERC is not proof that the schematic is correct. The ERC checks that pins are connected to something reasonable. It does not check that they are connected to the right thing. On a board with this many driver-to-matrix nets, the failures that are most likely to happen are a wire that ends a fraction of a millimetre off a pin, or a row swapped with a column. Neither produces an ERC violation. The way to check that is to export the netlist and read what it says: which nets exist, and what is on them. Export it with “File” then “Export” then “Netlist…”, and leave the format on the KiCad tab. What you get is a plain text file listing every net in the design and every pin on it. There is nothing proprietary about it, and you can open it in any editor.

Reading ninety-odd nets by eye is slow, error-prone work, and it is exactly the kind of work a computer should be doing. So the project files include tools/checknet.py, a hundred-line Python script that reads the netlist and checks it against what this board is supposed to be. This script is not part of KiCad, and it doesn’t use the KiCad API. It simply opens a text file and reads it. I did not write it by hand. Instead, I described the checks I wanted the script to perform to Claude, an AI assistant from Anthropic, and it produced the script. I then checked and confirmed its work, which is the part that matters and the reason I am willing to include it in the book.

I decided to create this script because of a real defect on this board. While wiring the cascade I ran a wire horizontally from one cell’s DOUT to the next cell’s DIN. Those two pins sit at the same height on opposite sides of the chip, so the wire passed straight through the next driver’s DOUT pin on its way across, and the four separate links became one net. All four drivers ended up wired in parallel, listening to the same signal. The sheet looked correct, the ERC reported nothing, and the board would have gone to the fabricator that way. The netlist is what found it.

Run it from the project directory:

python3 tools/checknet.py net.net --cell 1     # repeat for cells 2, 3 and 4
python3 tools/checknet.py net.net --cascade 4

The --cell form asserts that a cell’s sixteen SEG and DIG nets hold exactly two pins each, the driver’s and its own matrix’s, and that both of the driver’s ground pins are tied. The --cascade form follows the chain, checking that each DOUT reaches only the next chip’s DIN, that CLK and LOAD reach all four drivers, and that the four DIN nets are still four distinct nets rather than one. That last assertion is the one that would have caught the wire above. A passing run says so:

  OK   cell 1: 16 SEG/DIG nets exclusive to U1<->DS1, both grounds tied
  OK   cascade: DOUT->DIN chain over 4 cells, CLK/LOAD shared, DINs distinct

Run with no options at all, it prints every net and the pins on it, which is worth doing once for the picture it gives you.

Figure 7.25: The five checks passing on the finished project. The four --cell runs are the ones that prove each driver reaches its own matrix and nothing else, sixteen nets at a time; the --cascade run is the one that proves the chain is a chain, rather than four drivers wired in parallel and looking perfectly correct on the sheet. This is the output the schematic has to produce before the layout is worth starting.

This script is written for this board alone. The MAX7219 and matrix pin numbers are typed into it, so it is not a tool you can point at your next design. What to take from this is that KiCad’s exports are plain text, so any check you can describe in words you can also write down and run. Volume 3 takes this up properly, in the part on extending KiCad with Python.

Board and Layout

You are on the eight-step layout workflow from Volume 1’s Chapter 5. There are two things about this board that are different from the previous boards in this book. The first is that part of the board is repetitive, and as a result a large portion of the placement and routing can be done once and copied rather than drawn four times over. The second is that the board’s through-hole parts do not share a measurement system: the TA08-81GWA matrix (DS1 to DS4) is metric on a 2.5 mm pitch, the Arduino Nano is imperial on 2.54 mm, and the switch and buttons are metric again on spacings of their own. This means that the grid you have used since Chapter 3 cannot reach the position the matrices have to land on. We will address both issues below.

Here is the board you are working toward (Figure 7.26). Keep it beside you, as you did with the finished sheet.

Figure 7.26: The finished layout for the LED matrix array, with the ground pour hidden so that the tracks can be read. The four matrices sit edge to edge across the top as one display band, DS1 to DS4. Everything that exists once is in the row beneath: the Arduino Nano placed in landscape at the left with its programming socket labelled DATA at the board edge, the two buttons labelled MODE and SELECT, the slide switch between ON and OFF with Q1, R9 and R10 beside it, and J1 at the right edge under POWER and 5V 1.5A MIN. A mounting hole sits inside each filleted corner.

The plan behind this layout is to place the four matrices at exactly 20.0 mm apart and lock them. We will lay out and route one cell on the back of the board, behind its own matrix. Then we will get KiCad to copy that cell onto the other three, positioning each copy against its own matrix so that the exact pitch survives the copy. What remains after that is the shared wiring, the copper pour, and the checks.

Millimetres, not mils. Back in “Sourcing the Parts” you measured the matrix’s pin pitch and found 2.5 mm rather than 2.54 mm. That measurement decides which grid you work on for the rest of this board.

Two dimensions of the matrix are most important here. The first is its pin pitch, meaning the distance from the centre of one pin to the centre of the next along a row, which is 2.5 mm. The second is the width of its body, which is 20.0 mm, or exactly eight pin pitches. Because the four matrices have to sit edge to edge with no gap between their bodies, the horizontal spacing from the centre of one matrix to the centre of the next must also be 20.0 mm.

Let’s examine that requirement against the grid. The 100 mil grid you have used since Chapter 3 is 2.54 mm, and it moves a part in whole steps of that size. One step is 2.54 mm, two steps are 5.08 mm, three steps are 7.62 mm, and so on. No number of steps adds up to 20.0 mm. Seven steps come to 17.78 mm and eight steps come to 20.32 mm, so the closest this grid can put the second matrix to its correct position is 20.32 mm from the first, which is 0.32 mm too far.

That error repeats at every join. Four matrices have three joins between them, so the fourth matrix ends up 0.96 mm to the right of where it belongs, and the display band measures 80.96 mm across instead of 80.0 mm. Each join opens by a further 0.32 mm, and a display that should read as one screen reads as four panels placed near each other.

To address this discrepancy, we will work this board in millimetre grids (Figure 7.27). A 1 mm grid suits the outline, and 0.25 mm or 0.5 mm suits the parts that have no exact position to hit. One thing to know before you set them is that the grid list, the fast-grid shortcuts and the overrides below are all KiCad preferences rather than project settings, so they follow you into every board you open next, including the imperial ones from Volume 1. Change them for this board, and change them back when you go back to an imperial design. The important habit, though, is knowing when to stop using the grid at all. The four matrices are not nudged into place on any grid; their positions are typed, which is what the next step does. When you route, let the router snap the track to the pad rather than to the nearest grid point, so that a 2.5 mm pitch part and a 2.54 mm pitch part can share a board without either of them having to sit on the other’s grid. KiCad also lets you give different kinds of object their own grid, under “Preferences” then “PCB Editor” then “Grids”, where a set of grid overrides can put footprints on one spacing and tracks and text on another. The whole set can be switched on and off from the left toolbar, so it costs nothing to try.

Figure 7.27: The Grids page of the PCB Editor’s preferences, set up for this board. The list on the left is scrolled down to its millimetre entries, with the 1 mm grid active. “Fast Grid Switching” puts 1 mm on “Alt+1” for the outline and 0.25 mm on “Alt+2” for fine work, so the two grids this board needs most are a keystroke apart. KiCad keeps several points to measure from. We will work with reference to those points shortly, so it is worth taking a short detour to explain what they are. An ‘origin’ is a zero point, the place coordinates are counted from. The ‘page origin’ is fixed at the top-left corner of the drawing sheet and cannot be moved, and it is the one KiCad has been measuring from so far. The ‘grid origin’ is the point the grid lines up on, and this one you can put wherever you like. If you move it, every grid dot on the canvas will move with it, so positions are counted from the point you chose. Dialogues can work from it as well, including the placement dialogue in the next step. By customising the grid origin, you can use board dimension referencing rather than sheet referencing. Two further origins exist that this board does not need. The drill/place file origin is the zero that fabrication outputs can be measured from, and the local origin is the temporary one you set with the space bar, which is how you placed the second pad of the DRV8833 footprint in Chapter 2.

Step 4, route the tracks. You route one cell here, and KiCad routes the other three.

Start with cell 1, and route it as though it were the only cell on the board. The sixteen driver-to-matrix connections are the bulk of it, and they are easier than they look, because the matrix is a through-hole part whose pads are reachable from both sides while the driver is a surface-mount part on the back. Most of them therefore stay on B.Cu, short and parallel. The rest cannot, because of where the two devices’ pads land. To reach their own pin they have to cross a path that another connection already occupies, and two tracks cannot cross on the same copper layer. Each of those takes a single via up to F.Cu and finishes its run on the front (Figure 7.46). One via is enough, rather than one up and one back down, because the pad at the far end is a matrix pin, and a through-hole pad is reachable from either side of the board. The Default class routes them at 0.25 mm, and remember the arithmetic from the net class discussion: a row net carries the whole active digit, about 320 mA, and 0.25 mm of 1 oz copper carries about 0.87 A, so the margin is nearly threefold.

Figure 7.46: DS1’s sixteen driver-to-matrix connections routed, with the local power still to come. Most of them run the whole way on the back copper. The ones that meet a track already in their way each take a single via up to F.Cu and finish on the front, at a matrix pin that is reachable from that side because it is a through-hole pad.

Continue with the local power. Run a short GND track from each of the driver’s two ground pins, 4 and 9, to the ground pads of C1 and C2, and take +5V from the other side of those capacitors to the driver’s V+ pin and to R1. Keep those runs tight. The point of local decoupling is that the capacitor supplies the current burst from as close to the chip as possible.

Two things about that +5V run are worth settling before you draw it. The first is its width, because the Power class asks for 1.00 mm but 1.00 mm is too wide for the available space. The run has to pass between the driver’s ISET track and one of the row nets, and at full class width it comes within 0.20 mm of the first and 0.25 mm of the second, both inside the class’s own 0.3 mm clearance. Draw it at 0.800 mm and it clears everything. This is what the “Power minimum width” rule from board setup is for. It defines a floor for the class at 0.8 mm rather than pinning it at 1.00 mm, so a run that cannot have the optimum still has an acceptable width to fall back on, and the check still catches anything smaller than the floor.

The second is that +5V does not need to leave the back copper. It will arrive in this cell from the west and leave for the east, both on B.Cu, so draw it out to the edges of the cell and stop there. GND is the rail that needs to reach the front, so drop two GND vias on the capacitor side of the driver. The ground pour under the display band is going to be cut into strips by the sixteen tracks you have just drawn, and those two vias are what tie this cell’s ground to the front-side pour where the back-side copper cannot get through.

One thing to get right before you go further is to select the cell’s rule area and enlarge it so that it encloses every track you have just drawn (Figure 7.47). KiCad copies a track to the other channels only when that track is completely inside the reference area. If a run crosses the boundary then the other three cells will not receive it. The target areas resize themselves to match when you run the copy, so this is the only one you have to adjust. On this board, some track segments will fall slightly outside the edges of the rule areas, so the repeat function will not capture them and you will need to finish them by hand.

Figure 7.47: The reference cell, routed. Nine of the sixteen driver-to-matrix connections run straight across on the back copper; the other seven, seen mid-route in Figure 7.46, each rise through a single via and finish on the front at their matrix pin. The local decoupling runs are kept short, and two vias beside the capacitors carry GND up to the front, which +5V never has to do because it crosses the band on the back. Now let’s complete the copy operation. Select cell 1’s rule area and open “Tools”, then “Multi-Channel”, then “Repeat Layout…” (Figure 7.48). The area you selected becomes the “Reference”, every other placement area becomes a “Target”, and KiCad checks each target against the reference before it copies anything. That check compares parts and connections rather than reference designators, so R1 in the reference does not have to become R2 in the next cell; it becomes whichever resistor is wired the same way. A target that matches reports “OK” and arrives ready-ticked. A target that does not reports the reason and cannot be selected, and the reason will be a real difference between your cells rather than a complaint about the tool.

Before you click OK, set “Anchor footprint” to the matrix. Left empty, each channel is positioned relative to the centre of its own rule area, and a rule area is a boundary drawn around wherever the parts happened to be sitting, so nothing about it is exact. Name the matrix as the anchor and each channel positions itself against its own matrix instead. Those four are locked at exactly 20.0 mm, so the precision you typed in step 3 is inherited by everything the copy brings with it. Tick “Copy footprint placement”, “Copy routing” and “Include locked items”, leave “Copy other items” unchecked, then click OK. “Include locked items” matters specifically on this board: the reference cell’s matrix, DS1, is locked, and without it ticked the tool would leave it out of what it treats as part of the cell.

“Copy other items” matters for a reason its name does not prepare you for. Among the things it copies is the reference group’s own name, so ticking it hands every target the name Group DS1, and the four names you set in Figure 7.44 are gone. They are quick enough to type back in, and quicker still not to lose, which is why it is struck through in the figure.

It is also worth knowing that this is repeatable. If you later decide the decoupling in cell 1 should be routed differently, change it there and run “Repeat Layout” again, and the other three are redrawn from the reference as it stands. Nothing was baked in at the moment you clicked OK.

The shared wiring. Route the rest in this order, working from the highest current to the lowest.

  1. The input. VBUS from J1 to Q1’s source, and +5V picked up again at Q1’s drain. Both are in the Power class, so both come out at 1.00 mm without you choosing a width. You pick the net, and the width comes from the class.
  2. +5V out of Q1 and round to the band. Take the 1.00 mm front-copper rail west out of Q1’s drain, along the strip between the bottom of the display band and the row of switches, then turn down past the Nano. The rail itself carries on the long way round: 43 mm west along the bottom edge of the board, 28 mm north up the left margin, and then straight down through a single via just west of DS1.   3. +5V across the display band. Most of this is already drawn, because each cell got its own +5V when KiCad copied the reference. What is missing is the joins. Add three short 0.800 mm hops on the back, C1 to R2, C3 to R3 and C5 to R4, plus the stub from the via into R1, and the four cells become one chain running the full width of the band.

  6. The buttons. MODE and SELECT back to D2 and D3. The supply side of both pull-ups was picked up in item 2 above, so this is two signal runs and nothing more.

Shared wiring 1, the input. This raises the same problem you met inside the reference cell. There it was the neighbouring tracks that left no room for the Power class’s 1.00 mm, and 0.800 mm was enough to settle it. Here it is the footprint itself, and 0.800 mm is not enough. J1’s two VBUS contacts, met when the receptacle was placed, sit on a pitch set by the USB-C mechanical spec rather than by this board, and there is no room to bring a full-width track out of either pad without crowding the GND pad or shield tab beside it. KiCad refuses the track at 1.00 mm outright. The fix is to draw this one short run narrower, at 0.7 mm (Figure 7.50).

Figure 7.50: The VBUS track leaving J1, drawn at 0.700 mm. The track width field in the top-left toolbar (boxed) shows the value chosen for this run, well under the Power class’s 1.00 mm default. The arrow points to where the track leaves pad A9: J1’s VBUS pins sit on a pitch too tight for a full-width Power track to clear the neighbouring GND pads, so this one short run has to go narrower than the rest of the class.

Narrower is not the same as underpowered. Run the same arithmetic Chapter 3 taught you and 0.7 mm of 1 oz copper works out to about 1.8 A, comfortably clear of the 1.3 A that this board draws at its worst case. J1 gives you two VBUS pads for exactly this situation, so the current actually splits across two 0.7 mm runs into Q1’s source rather than travelling on one, and both the connector and the AO3401A are rated well past what either run will ever carry. The 1.00 mm class width was never a current requirement. It is headroom, chosen because the board had room for better, and this one corner of the board does not.

That still leaves the rule. The “Power minimum width” rule floors every Power-class track at 0.8 mm, and nothing in it makes an exception for J1’s pad pitch, so a 0.7 mm VBUS track fails the check as drawn (Figure 7.51). Weakening that floor for the whole class would undo the reason it exists everywhere else on the board, so the fix is a second, narrower rule that names the net directly, A.NetName == 'VBUS', rather than the class. KiCad resolves two matching rules by taking the last one written, so placing the new “VBUS minimum width (J1 pad-pitch relief)” rule after “Power minimum width” in the Custom Rules editor lets it override the floor for VBUS alone. +5V and GND stay held at 0.8 mm; VBUS drops to 0.7 mm, and only VBUS.

Figure 7.51: The Custom Rules editor in Board Setup, with the new rule boxed. The original “Power minimum width” rule still floors every Power-class track at 0.8 mm. The new “VBUS minimum width (J1 pad-pitch relief)” rule beneath it matches on the net name directly, A.NetName == 'VBUS', and because KiCad resolves conflicting rules by taking the last match, this one overrides the general floor for VBUS alone, lowering it to 0.7 mm while +5V and GND stay at 0.8 mm.

With both rules in place the tracks go down as they should: VBUS in from J1 on its two pads, through Q1, and out as +5V toward the rest of the board (Figure 7.52).

Figure 7.52: VBUS and +5V clear of J1 and Q1. Each of J1’s VBUS pads carries its own 0.7 mm run into Q1’s source, GND returns through the shield pads on either side, and +5V leaves Q1’s drain into the rest of the board.

J1 causes one more violation, of a different kind. Run the DRC now and two clearance violations come back, both inside the connector itself: VBUS on pad A9 against CC2 on pad B5, and VBUS on pad B9 against CC1 on pad A5. The gap in each case is 0.29 mm, and the Power class asks for 0.30 mm. No track is involved, so it is not a routing mistake, and those pads are where the USB-C specification puts them, so there is nothing to move. What you are looking at is what happens when a net class lands on a footprint the class was never sized for. You have set up the net classes so that anything carrying VBUS requires 0.3 mm of space around it, and one of the things carrying VBUS is a pad 0.29 mm from its neighbour.

There are three ways out and only one of them is right. Loosening the Power class clearance to 0.25 mm would fix it and would also loosen every power track on the board, which is the reason the class exists. Excluding the two violations by hand would silence them until the next time somebody regenerates the report. The third way is a rule that says exactly what you mean, which is that pads inside J1 may sit as close to each other as the connector’s own design puts them:

(rule "J1 internal pad clearance (USB-C pad pitch)"
    (constraint clearance (min 0.2mm))
    (condition "A.memberOfFootprint('J1') && B.memberOfFootprint('J1')")
)

The expression memberOfFootprint() asks whether an object belongs to a named footprint, and requiring it of both A and B is what keeps this narrow. The relief applies only when both objects are part of J1, so the clearance between J1 and anything else on the board is untouched, and so is every other Power-class object. This drops the floor to 0.2 mm, which is the Default class clearance and still well above what any fabricator will ask of you. Type it into the same Custom Rules editor, below the other two, press “Check Rule Syntax”, and the input stage is finally clean (Figure 7.53).

Figure 7.53: All three of this board’s custom rules in the Custom Rules editor, with the new one boxed. The two above it constrain track width and were written while routing the input; this one constrains clearance, and it is the only one of the three that has nothing to do with anything you drew. Both halves of its condition name the same footprint, which is what confines the relief to the inside of J1 and leaves the clearance between J1 and the rest of the board at the Power class’s 0.3 mm.

That is the second time on this board that a rule has been written to describe a physical fact rather than a preference. When the DRC reports something you cannot change, the answer is usually a narrower rule, not a weaker one.

Shared wiring 2 and 3, the +5V rail. With the input settled, +5V leaves Q1’s drain and has to reach six places: the four cells, the Nano’s 5V pin, and the two button pull-ups (Figure 7.54).

Figure 7.54: The +5V rail complete, front and back. The wide front-copper run leaves Q1 at the right, drops past the Nano where branches take it to the Nano’s own 5V pin and to the two button pull-ups, then goes the long way round, along the bottom edge and up the left margin, to a single via just west of DS1. Everything from that via onwards is on the back, where one chain threads through all four cells inside the clear channel between the matrix pin rows.

Two things about that picture look like the wrong choice until you work them out. The first is the detour. Q1 sits at the right-hand end of the board and the rail could have crossed to the left in a straight line, so going round three sides of the board looks like waste. It is about 120 mm of 1.00 mm copper, which is 60 mΩ, so even if the whole 1.3 A travelled the whole length it would cost under 80 mV, and it does not, because the Nano and the pull-ups tap off a quarter of the way along. What the detour protects is the middle of the board. The front copper between the display band and the Nano is the only clear corridor those two parts share, and a 1.00 mm rail laid straight across it would put the widest obstacle on the board in the one place everything else might later need to cross. Sent round the edges instead, the rail runs through space that nothing else needs. As it turns out, neither CLK nor LOAD needed that corridor, but you do not know that yet when you route the power, and that is the point of working from the highest current down. The widest track is drawn first, so give it the space you can most afford to give away.

The second is the single via. A rail feeding four separate cells looks like it requires four vias, one per cell, and it would if the cells were fed from the front. They are not. The chain sits inside the 13.3 mm channel between the matrix pin rows, under the matrix bodies, on the back copper, with no matrix hole anywhere in its path. That channel is clear on both layers precisely because the project’s footprint puts its pins along the top and bottom edges, which is the reason I chose that footprint over a catalogue one back in “Sourcing the Parts”. Cross the band on the back and one via does the work of four.

A chain does mean the first leg carries everything. The run from the via into R1 and on through cell 1 feeds all four drivers, which is 4 × 320 mA, or 1.28 A, with all four sitting on their active digit at once. Each leg after that carries one cell less, until cell 4 is drawing its own 320 mA down the same 0.800 mm track. Put 0.800 mm through the Track Width calculator on the same basis as before, 10 °C rise and 1 oz copper, and it returns about 2.0 A, so even the busiest leg keeps better than a 1.5× margin. Feeding the chain from one end rather than splitting it in the middle does cost something, roughly 30 mV of extra drop at the far end, and in exchange the power crosses the band in the same direction as the cascade. That is worth 30 mV when you come back to read the board in a year.

Shared wiring 4, CLK and LOAD. Both signals go from the Nano to all four drivers, so before drawing either one, decide the shape. There are two ways to give four devices the same signal. A star sends a separate branch to each device from a common point. A daisy chain sends one track that calls at each device along its way. Use the chain, for both.

The routing argument is that the drivers sit in a row at 20 mm centres, so one track threading past all four is the shortest copper and the simplest route, while four branches would all have to leave the same crowded corner beside the Nano.

The electrical argument points the same way. A star splits one output into four lines at a single point, which is an impedance step with four unterminated stubs hanging off it. This topology can introduce ringing on a clock edge, degrading the clock signal. Skew is not a reason to prefer the star here, because LOAD latches data that took microseconds to shift in, and the few hundred picoseconds between cell 1 and cell 4 are very small to worry about. Star routing matters most on buses where arrival times must match to within a fraction of a clock period. This is not one of those.

What the chain does not have to be is symmetrical, and on this board it is not (Figure 7.55). The two signals take opposite sides of the display band and different layers, and the reason is in the driver’s pinout. The MAX7219 brings LOAD out on pin 12, along its south edge, and CLK out on pin 13, along its north edge. Each signal leaves on the side it is already on.

Figure 7.55: CLK and LOAD routed, on opposite sides of the display band. LOAD runs below the band on the back copper without a single via, because the drivers are on the back and the Nano’s header is through-hole, so both ends of every hop are already there. CLK runs above the top matrix pin row on the front, because the back copper north of the drivers is full of the sixteen runs each cell needs, and drops through one via at each driver to reach pin 13.

The LOAD track is the tidier of the two. Every device it touches is reachable from the back. The four drivers are surface-mount parts on B.Cu, and A1’s header is through-hole. So LOAD runs the whole way on the back and uses no vias at all. It also forks rather than running end to end, because the Nano’s LOAD pin sits between U1 and U2; the chain goes west to U1 and east to the other three from the point where it arrives. A chain fed from the middle is still a chain, and here it saves about 19 mm of doubling back.

The CLK track could not do the same. Pin 13 is on the drivers’ north edge, and the back copper north of the drivers is where the sixteen driver-to-matrix runs live, so there was no room. The front, though, is empty in the narrow strip above the top row of matrix pins, and that is where CLK goes. Up the left margin from the Nano, then east along that strip, dropping through a via at each driver in turn. It clears the pin row by 0.425 mm the whole way. Four vias against LOAD’s zero is not a worse result. It is what the pinout costs on that side, and paying it on the front is cheaper than trying to find room on the back.

Shared wiring 5, the cascade. All four runs are Default class at 0.25 mm, and there is nothing to decide about width or current here. What there is to notice is where each one changes layer, and the driver’s pinout decides that as surely as it decided the shape of CLK and LOAD.

DIN is pin 1 and DOUT is pin 24, which on a rotated MAX7219 puts them at the same end of the package: DIN at the east end of the driver’s south pad row, DOUT directly above it at the east end of the north row, 9.3 mm apart. A link therefore starts at the top of one driver and has to arrive at the bottom of the next, 20 mm east. It leaves DOUT on the back, rises through a via in the seam between two matrices, runs down the front through that seam, heads east under the next matrix in the strip below its bottom pin row, and drops through a second via into that driver’s DIN. Two vias per link, six for the three of them. DIN1 needs one, because it starts at the Nano’s through-hole header and can stay on the front until the via beside U1.

Notice what the three band-crossing signals have between them now. CLK on the front above the top pin row, the cascade on the front below the bottom pin row, and LOAD on the back below the band. Three lanes, and no two signals have to share one. Each signal is where its own pin put it.

Route DIN1 into U1, then route LINK1 in full, from U1’s DOUT all the way into U2. Then stop drawing, because the two links left are the same shape as the one you have just drawn.

What the Copy Cannot Make Identical

The four cells on the finished board are not perfect copies of one cell. Two of the differences are real and intended, one at each end of the cascade. A third kind of difference is damage, and it turns up wherever two cells meet. Each of the three calls for a different response. One needs nothing at all from you. Another needs a deletion that no check on this board will ask for. The last is the damage Figure 7.57 has already shown you.

  1. Cell 1 is unlike the others at its input. U1 takes its data from the Nano’s D11 on the net DIN1, while U2, U3 and U4 take theirs from the previous cell’s DOUT, on LINK1, LINK2 and LINK3. That is the difference that made a second “Repeat Layout” pass necessary, seen now from the other side. The run arriving at U1 comes from the south-west and crosses under DS1 on a line of its own, and no amount of copying will make it resemble the three that follow it. Cell 1 is the reference, so there is nothing to repair here. There is only something not to be alarmed by.
  2. Cell 4 is unlike the others at its output, and this one you do have to fix. U4’s DOUT on pin 24 is the end of the chain, so it goes nowhere. The schematic left it bare back in Figure 7.20, and the netlist records it as unconnected-(U4-DOUT-Pad24). The first copy pass, though, took cell 1 as its reference, and cell 1 has a link leaving DOUT. Every target cell therefore received one, including the last, so U4 now carries a short track running out of pin 24 towards a fifth cell that does not exist. Delete it.
  3. Every boundary between two cells needs reading by eye. There are three of them, one per link, and each is the kind of place Figure 7.57 came from. Work along the display band from west to east and check each hop twice: once for the break that the “Unrouted” count will show you, and once for the damage that it will not.

Item 2 is worth a moment on its own, because finding it is the most transferable thing in this section. The “Unrouted” count will not move, since an unrouted count measures connections that are missing and this is copper that is surplus. The DRC will not object either, because a stub of legal width on a legal net at a legal clearance is legal. Both checks are working correctly and both are silent. The only thing that finds this track is you, reading the end of the chain and asking what it is for. Figure 7.57’s damaged link makes the same point from the opposite direction: a fault that breaks something is reported, and a fault that merely adds something is not.

What you should not do is tidy up the rest. Four cells repaired by hand at three different boundaries do not come out to identical coordinates, and on my board they did not. The ground stitch beside each driver sits a few tenths of a millimetre from where its neighbours’ sit, one cell’s version of it is drawn with one segment fewer than the others, and here and there a drag has left behind a fragment of track a fraction of a millimetre long. None of that costs anything, because all of it is legal copper on the right net, and the surest way to disconnect a track you have just repaired is to drag it again so that it matches its neighbour. Symmetry is worth having while you draw, and it is not worth pursuing once you have made repairs.

Step 5, add copper fills. Pour GND on both copper layers. Two reasons apply here, and both come from the power budget. The first is that this board returns up to 1.3 A to its source, and a pour is the widest conductor a two-layer board can offer. The second is that the four drivers sit on the back, each drawing a 320 mA burst several thousand times a second, and each of them needs the shortest possible path to ground.

Draw one copper zone for the GND. A single zone object fills on as many copper layers as you tick, so take the “Add Filled Zone” tool from the right-hand toolbar, or press “Ctrl+Shift+Z”, and click once inside the board outline. The Copper Zone Properties dialogue opens on that first click, before you have drawn anything else, and that is where you tick both F.Cu and B.Cu in the layers list at the left and set “Net name” to GND (Figure 7.61). Accept it, place the remaining corners a millimetre or so inside the board edge, and double-click to close the outline. Each layer fills independently, and both carry the same net.

Figure 7.61: The Copper Zone Properties dialogue as this board’s ground pour is set up. The layers list at the left is a column of tick boxes rather than a single choice, and both F.Cu and B.Cu are ticked, so one outline produces both fills. “Net name” is GND. Of the settings below, three decide the shape of what you are about to see: the clearance, the minimum width, and “Remove islands”, which is set to “Always”.

Three of those settings deserve a moment before you fill, because between them they decide what the pour will look like:

  1. Clearance, 0.2 mm. This is the gap the fill keeps from copper on other nets. It is not the last word, though: GND is in the Power class, which asks for 0.3 mm, and where a zone setting and a class setting disagree KiCad takes the larger. The fill will keep 0.3 mm whatever this field says.
  2. Minimum width, 0.25 mm. Any neck of copper the fill would have drawn thinner than this is dropped instead of drawn. This is the setting that decides whether the fill reaches between two tracks or stops short of the gap.
  3. Remove islands, “Always”. After filling, any area of the zone that reaches no pad on the zone’s net is deleted. Not flagged, not left in place for you to judge: deleted.

Below them, “Pad connections” is left at “Thermal reliefs” with a 0.5 mm gap and 0.5 mm spokes, which is the hand-soldering choice Volume 1 argued for, and which is why every ground pad on this board joins its pour through four short spokes rather than being swallowed by it.

Now press “B” and look at the result rather than assuming it. A pour is the one piece of copper on the board that you do not draw, which makes it the one whose shape you have not decided in advance.

The first fill on this board will look incomplete (Figure 7.62). Across the whole display band, on both layers, most of the copper is simply not there. The three settings above are the whole explanation. The sixteen driver-to-matrix runs in each cell, crossed by the +5V chain, cut the band into slivers; the minimum width dropped the thinnest of them before they were ever drawn; and of the ones that were drawn, the ones that reached no ground pad were removed as islands. What comes back on the back copper inside the band is seven small scraps. Nothing anywhere reports this. Island removal is not a violation, so it appears in no check and no count. The missing copper is an indicator that what the fill drew there reached no ground pad, so it was removed.

There are two things to do about all of this. The first is to move whatever is cutting the copper apart (Figure 7.63). The pour goes where the routing lets it go, so the routing is what has to change. With this adjustment, both layers gain ground copper, and the cut-off region under the middle of the board stops being a region at all, because it joins the main plane. Inside the band, the three front pieces grow noticeably, and the back’s seven scraps become ten larger fragments. Compare the cascade here with Figure 7.58: DIN1 and the three LINK runs take different paths now, and the tracks and vias beside them have been nudged aside to make room. Refill the fill again after that and it is still in pieces. The back-side pour is in eleven separate pieces, because the sixteen tracks each cell needs and the +5V chain crossing the width of the band have to run somewhere. Each driver’s two ground pins land on one piece and that same cell’s two decoupling capacitors land on a different one, so the return path from a capacitor to the chip it is decoupling leaves the back copper, crosses to the front and comes back. This is what the two ground vias per cell in Figure 7.47 are actually for, and it is why we’ll have to use stitching vias next.

The second is to stitch what survives, placing the vias where the fill needs them. This board went from 8 ground vias to 34. Two of the new ones sit outside the band, one in the button and Q1 region and one beside J1, and those two retire the single-pad dependencies. The rest go inside the band, seven to nine per cell, until every surviving piece of pour on either layer has its own tie to the other side. Drop each one on bare pour with the free-via tool and it picks up GND from the copper beneath it without your typing the net, which is the behaviour Chapter 4’s via stitching section describes.

Press “B” afterwards and read the pour again, and expect it to look exactly as it did before, because a stitching via changes nothing about the shape of the copper it sits in. The two front regions outside the band are still two regions, still separate from the front plane. What has changed is where each one goes next. Instead of leaving through one pad, each now drops straight into the back plane, which is the piece of copper that carries the current anyway. Bonding a region to the other layer is what stitching does. Stitching ties layers together, and routing decides the shape of the copper on each one.

KiCad does not refill a zone by itself, so press “B” after every change, before you check anything or export anything. Press it once more now, and the copper is finished. Read the two layers separately when you do, one at a time in the appearance panel rather than both stacked (Figures 7.64 and 7.65). Stacked, this board looks like a solid sheet of ground with some tracks on it. Taken a layer at a time, it looks like what it is.

Figure 7.64: The finished pour on the front copper, with the back hidden. Everywhere outside the display band it is one plane, and the wide Power-class rail crossing it stands out for the reason it always has: a class you set before the first symbol was placed. Two smaller regions in the lower right are separate pieces rather than part of that plane, one around the buttons and Q1 and one around J1, and the gaps that separate them are narrow enough that you will not find them by looking. That is the whole problem with a fill you have only glanced at. Inside the band, the front copper is in three pieces, sitting across the seams between the matrices, which is where the sixteen tracks per cell leave room for it.

Figure 7.65: The same board, back copper only. This is the layer that carries the return current, and everywhere outside the display band it is a single unbroken plane. Inside the band, the sixteen driver-to-matrix runs in each cell and the +5V chain crossing them leave ten fragments, and each cell’s driver sits on a different fragment from its own decoupling capacitors. Compare this with the same band in Figure 7.62, where the first fill left seven much smaller scraps, and the difference is what re-routing DIN and the links bought.

Step 6, the design rules check. Run the DRC from the “Inspect” menu with “Refill all zones before performing DRC” ticked, and read what comes back rather than counting it, exactly as you did with the ERC. Three things on this board come up.

The first is that four matrices placed at exactly 20.0 mm put four courtyards side by side with nothing between them, and a courtyard overlap is a violation. The project’s footprint insets its courtyard to 19.9 mm for precisely this reason, which leaves 0.1 mm of space between neighbours, so the check raises no violation here. A catalogue footprint drawing a full-body courtyard would report three overlaps here, and you would have to decide whether to edit the footprint or widen the gaps between the matrices. That is the result of choosing this footprint.

The second is the four mounting holes. Four parts with no symbol behind them ought to be four complaints, and the “Schematic Parity” tab reports seven. Four of them are “Extra footprint”, one per hole, which is the expected one. The board holds a footprint the schematic doesn’t know. The other three are “Duplicate footprints”, and they are a second-order effect of the first. A mounting hole is placed straight onto the board rather than pulled through from a symbol, so nothing ever gave it a reference designator, and all four still read REF**. KiCad compares designators, finds the same one four times over, and reports three collisions. So a warning about duplicates is really a report of four parts with no designator at all. The same pair of messages turns up together on every board that carries board-only parts. Read each of the seven, satisfy yourself that it is a hole you placed, and leave it or exclude it as you prefer.

The third is a check on your own work, and it is the only one you have to break something to see. Pick a stretch of +5V somewhere convenient, select it, and set its width to 0.25 mm in the Properties panel (Figure 7.66). Any stretch will do; the one in the figure is a 3.3 mm run on the back copper between Q1 and the first cell.

Figure 7.66: Breaking the board on purpose. The Properties panel edits the selected track directly, and setting “Width” to 0.25 mm leaves the thinned stretch visibly narrower than the +5V running either side of it. Nothing objects at the moment you type it, which is the point: the board editor will let you draw an underweight power track all day, and only the DRC will report it.

Now run the DRC again (Figure 7.67). The custom rule you typed during board setup fires, and the report names it, so you are not left to work out which constraint objected. Put the width back and the violation goes away. Doing this once turns that rule from something you typed into something you have seen work, and it is far cheaper to learn it here than on a board where the rule is the only thing standing between you and an underweight power track.

Figure 7.67: The DRC reporting an error. The error reports a track width problem, the rule that caught it is named in the message as Power minimum width, and the two numbers are the constraint and the offence, 0.8000 mm required against 0.2500 mm found. The line beneath identifies the track itself, +5V on B.Cu, 3.3000 mm long. That is what a custom rule buys you over a global constraint: the report tells you which of your own rules objected, rather than reporting a bare minimum-width failure you then have to trace back to a setting.

Fix, refill, re-run, and repeat until the report is clean (Figure 7.68). On a board with this many nets that loop takes a few passes, and every pass is cheaper than the first prototype.

Be clear about what “clean” means here. In this project, “clean” means zero violations, zero unconnected items, and seven warnings you have read and can account for.

Figure 7.68: The check that ends the layout. “Violations” and “Unconnected Items” both read zero, which is the pair that decides whether the board can be made. The seven entries under “Schematic Parity” are the mounting holes, four reported as extra footprints and three as duplicate designators, and they are shown here as they arrive rather than excluded. Notice that there is no mention relating to the four courtyards placed along the display band, which is the custom footprint’s inset courtyard doing its job without raising a violation.

Step 7, add text and silkscreen. Most of your silkscreen arrived with the footprints, as reference designators, and on a board of thirty-two parts they will be larger than you want. Restyle them in one pass with “Edit” then “Edit Text and Graphic Properties”, scoping the change to reference designators and setting a single size for all of them. This board uses 1 mm high with 0.15 mm strokes, which is comfortably above the 0.762 mm at 0.125 mm floor that arrived with the fabricator’s constraints during board setup, and small enough that thirty-two of them fit without overlapping.

The matrices need nothing beyond that. The footprint carries no silkscreen body outline at all, and that is deliberate, for the same reason as the inset courtyard. Four body outlines butted against each other would overlap, and silkscreen printed over a neighbour’s silkscreen is a violation on most fabricators’ rules. What it does carry is the two marks that matter. Its own reference designator sits clear of the body, so that a 20 mm part does not print its label underneath itself, and a filled dot marks pin 1. So DS1 to DS4 label themselves above the display band, and each one tells an assembler which way round it goes. That is the fifth time in this chapter that choosing the part carefully has made the work easier, after the free seam between cells, the *ROW* pattern, the clear channel for +5V, and the courtyard that raises no violation.

What does need your attention is the parts that came from nowhere. The four mounting holes and the three logos were placed straight onto the board rather than pulled through from a symbol, so none of them was ever given a designator, and all seven print REF** on the silkscreen. Open each one’s properties and untick “Show” on the reference field. Be clear about what that does and does not fix. It takes the text off the layer that gets printed, but the part still has no designator, so the seven “Schematic Parity” entries you read in step 6 remain exactly as they were. You are tidying the artwork, not addressing the DRC violations.

Finish with the labels a human needs to use the board (Figure 7.69). Give the board its name and version. Put MODE and SELECT under their buttons, and ON and OFF either side of the slide switch, so that its position means something. Beside J1, print what the board expects of its supply, POWER and 5V 1.5A MIN, so that the requirement travels with the hardware rather than living only in the schematic’s text notes. Then label the module and the socket at the far edge, Arduino Nano under A1 and DATA beside its USB port.

This board has two USB sockets, and only one of them feeds it with power. Place the text POWER at one end and DATA at the other in the front silkscreen.

The driver designators need no work either, because U1 to U4 came through onto the back silkscreen with their footprints, along with the decoupling capacitors. Check they are legible rather than moving them.

Logos go on last, and they are footprints rather than text. KiCad ships the Open Source Hardware mark and its own logo in the Symbol library, so you place them exactly as you placed the mounting holes. A logo of your own is made from a bitmap with the Image Converter and saved into a project library, which is where this board’s Tech Explorations mark comes from. All three are graphics on a silkscreen layer, which is why they cost nothing to fabricate, and why they arrive carrying a REF** of their own.

Figure 7.69: The finished silkscreen. DS1 to DS4 sit above the display band because the footprint puts them there, not because you placed them, and the small dot at the lower left of each matrix marks pin 1. POWER and 5V 1.5A MIN at the right label J1; DATA at the left labels the Nano’s own socket; between them they answer the one question an assembler is most likely to get wrong.

Step 8, view in 3D and generate the Gerbers. Open the 3D Viewer from the “View” menu, and the first thing to look at is the display band. Four separate parts should read as one screen, and if they do, the placement work at the start of step 3 did its job (Figure 7.70).

The second thing you will notice, the first time you do this, is that the Arduino Nano is not there. Nothing you did caused that, and it is worth a few minutes of your attention, because it is a situation you will meet again. The stock Module:Arduino_Nano footprint does carry a 3D model reference, pointing at Module.3dshapes/Arduino_Nano_WithMountingHoles.step. KiCad’s 3D model library does not ship that file. So the footprint holds a path to a model that does not exist, the viewer finds nothing to draw, and nothing anywhere reports a problem.

A missing model and a broken path look identical from the outside, and there is exactly one place that tells them apart. Open A1’s Footprint Properties and go to the “3D Models” tab. A footprint with no model at all shows an empty list. This one shows a path in the list and an empty preview beside it, and that combination is what a dangling reference looks like.

The repair is in the project files, and there are two routes to it. The finished project takes the first. Keep the stock footprint and enter the model path yourself, on the “3D Models” tab you are already looking at, pointing it at a VRML model of the Nano built from Arduino’s own open-source KiCad project. Alongside the path, the board sets the offset and rotation that stand the model up and turn its USB socket towards the DATA label. A second route is klp5e-ch07:Arduino_Nano, a copy of the stock footprint that carries the same model reference inside the footprint itself, so that changing A1’s footprint is all you have to do. Note that the two do not currently agree on the transform, so the library route puts the Nano flat on the board and turned around; if you take it, expect to adjust the rotation on the “3D Models” tab afterwards.

One trade-off comes with that fix. VRML models are for display only, so exporting this board to STEP will not include the Nano’s body. That is acceptable here, because the mechanical question this board actually poses is whether anything collides under the display band, and the Nano is nowhere near it. On a board where the Nano’s height decided whether a lid closed, you would want a STEP model instead.

Since A1 is the only part on this board that asks anything of you, it is worth seeing where the other thirty-one get their models from. Stock footprints arrive with theirs already attached, and the location follows a pattern rather than a lookup. The model library is the footprint’s own library name with .3dshapes on the end, sitting under ${KICAD10_3DMODEL_DIR}, and the file inside carries the footprint’s own name with a .step extension. So the resistors, whose footprints come from Resistor_SMD, take their model from Resistor_SMD.3dshapes, from a file named after the footprint. The upper list switches individual layers on and off. Board body, front and back copper, both silkscreens, mask, paste and the user layers. Finally, plot the Gerbers and the drill file from the “File” then “Plot” dialogue, exactly as you did in Volume 1’s Chapter 8. Two settings in the drill dialogue are easy to overlook and are the ones a fabricator actually cares about. The first is “PTH and NPTH in single file”, which you tick. The second is “Zeros”, which you set to “Decimal format”. KiCad’s default suppresses the leading zeros in each coordinate, and a quote page that cannot read your drill file will tell you the file is invalid without telling you why.

Take a moment over what that folder now holds. You have laid out a thirty-two part, two-layer board carrying 256 LEDs, and of its four identical cells you placed one and routed one. The other three came from a tool. That is the difference this chapter set out to show you, and it is the same difference whether a board repeats itself four times or forty.

The KiCad 10 Features This Board Puts to Work

The repetition in this board is what makes it a showcase for KiCad 10’s reuse and precision tools, so this is the project where I introduce them properly. Here they are gathered in one place, now that you have used all four:

  • Design blocks let you capture one cell’s schematic and drop the whole thing back in as a unit, which is what the schematic half of this chapter was built around. KiCad 10 extends the idea to the board as well, so that a block can carry its layout placement and routing along with its circuit. This board did not need that second form, because its four cells were already on the sheet by the time the layout began, and a board design block is at its best when you lay out one cell before the copies exist. Chapter 10’s recipe walks through it on a board built that way round.
  • Multi-channel design treats the four cells as repeated channels of the same circuit, which is how you placed and routed three of them without drawing a track. It is also how a later change to one cell is pushed to the others rather than edited four times, since “Repeat Layout” reads the reference as it currently stands every time you run it.
  • Precision positioning puts each matrix at an exact offset from a corner you chose, rather than at the nearest point some grid allows, which is the only reason the four panels read as one display.
  • The 3D viewer let you confirm the array looked right, and that nothing collided, before you committed to ordering it. It also showed you a footprint holding a path to a 3D model that does not exist, which is a fault worth being able to recognise.

The last three all belong to the layout half of the chapter, because they are all answers to questions that only come up once the parts are physical.

What You’ll Carry Into the Capstone

By the end of this project you will have taken a busy, repetitive board from schematic to 3D preview, and you will have done it without hand-drawing a single duplicated cell. That held on both sides of the workflow. On the sheet, one design block gave you four wired cells; on the board, one routed cell and a correctly chosen anchor gave you four laid-out ones, with the exact 20.0 mm pitch carried through the copy rather than approximated by it. You will also have met the trap that repetition sets. A design block reproduces its labels verbatim, so the links between cells have to be named after the stamping rather than before it, and a tidy horizontal wire from one cell’s DOUT to the next cell’s DIN shorts the whole chain without the ERC saying a word. The only thing that catches that is reading the netlist, which is why this chapter would not let you leave the schematic without it. Meeting that on a friendly board, where you can reason your way to the cause, is worth a great deal more than meeting it for the first time on a board you are worried about.

That is the layout half of Volume 2’s promise. The other half is authoring the parts that no library has for you, and that is what the capstone is for.
